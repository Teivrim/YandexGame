# NEON//COLLECTION

Сборник: пять игр серии в одном Android-приложении.

```text
neon-collection/
  index.html      меню: пять карточек, полноэкранная игра, кнопка «Назад»
  hub.css         тёмная неоновая тема серии
  hub.js          запуск игр, кнопка «Назад», мост хранилища
  catalog.js      список игр: название, жанр, описание, акцент, значок
  storage-shim.js прослойка localStorage для кадров игры
  icon.png        иконка приложения 512x512, рисуется кодом
```

Сборка: `node rustore/build-collection.js <out-assets> <корень репозитория>`,
APK: `powershell -File rustore/build-apk.ps1 -Game collection`.

## Почему всё лежит в одной странице

В APK игра открывается по адресу `file:///android_asset/index.html`, и на
`file://` **не работают оба** способа подгрузить игру из меню:

| Способ | Результат на `file://` |
|---|---|
| `XMLHttpRequest` к `games/oni.html` | заблокирован, приходит статус 0 |
| `<script src>`, созданный через `createElement` | не грузится ни с query-строкой, ни с абсолютным `file://` |
| `<script src>`, вписанный парсером в HTML | **работает** |
| `iframe.srcdoc` | **работает** |
| `iframe.src = blob:` | `SecurityError`, кадр становится чужеродным |

Отсюда решение: игры встраиваются в страницу как строки и пишутся в кадр
через `srcdoc`. Файлов в `assets` ровно один — `index.html` на 598 КБ.

## Почему игра уезжает за пределы меню

`srcdoc` выбран ещё и потому, что не добавляет запись в историю сессии,
в отличие от `src`. Иначе системная кнопка «Назад» на Android уходила бы
внутрь кадра вместо возврата в меню.

На всякий случай история ведётся и явно, а кнопка «Назад» в Android
спрашивает у страницы, открыта ли игра:

```java
web.evaluateJavascript(
    "(function(){try{return (window.NEON && window.NEON.current()) ? '1' : '0';}catch(e){return '0';}})()",
    value -> { /* '1' — закрыть игру, иначе canGoBack или выход */ });
```

У одиночных игр `window.NEON` нет, ответ будет `0`, и поведение
прежнее — правка в `make-project.js` им не мешает.

## Прослойка хранилища

Кадр, открытый через `srcdoc` со страницы `file://`, живёт на
непрозрачном происхождении, и его собственный `localStorage`
недоступен: обращение бросает `SecurityError`. Проверено и в браузере на
`file://`, и здесь.

Поэтому в начало каждой игры подставляется `storage-shim.js`: он
подменяет `localStorage` в кадре и перенаправляет вызовы родителю.
Родитель спускается в мост `AndroidStore`, если он есть, иначе в свой
`localStorage`.

Благодаря этому **ни одну из пяти игр править не пришлось**. Четыре игры
пишут прямо в `localStorage` и в APK сбора молча теряли бы прогресс;
прослойка даёт им то же надёжное хранилище, что и ONI с его мостом.

Ключи у игр разные и не пересекаются:

| Игра | Ключ |
|---|---|
| COURIER | `neon-courier-profile-v1` |
| BASTION | `neon-bastion-profile-v1` |
| DESCENT | `neon-descent-profile-v1` |
| VECTOR | `neon-vector-profile-v1` |
| ONI | `neon-oni-profile-v1` |

## Экранирование игр в строке

Игры вставляются в страницу отдельным шагом **после** сборки меню.
Это принципиально: `build-bundle.js` прогоняет файл через Babel, а тот
перепечатывает строковые литералы и возвращает `<\/script>` в
`</script>`. После этого парсер страницы обрывает тег `<script>` на
середине, и весь файл падает с `SyntaxError: Invalid or unexpected
token`. Экранирование, сделанное до Babel, не выживает.

Порядок внутри шага тоже важен: сначала `JSON.stringify` (он экранирует
кавычки и обратные слэши), и только потом `</` заменяется на `<\/`. Если
заменить раньше, `JSON.stringify` экранирует и наш обратный слэш, и в
документе не окажется ни одного закрывающего тега.

## Что проверялось

Не «собралось и не упало», а конкретные утверждения:

- на `file://` открываются все пять игр, `canvas` 1280, кадры рисуются;
- ни одного сетевого запроса и ни одного исключения;
- в каждой игре своя прослойка, `localStorage` в кадре работает;
- профили не смешиваются: подсеяны пять профилей с разными числами,
  каждая игра видит только свой, чужих на экране нет;
- запись из кадра доходит до родителя у всех пяти;
- кнопка «Назад» возвращает в меню, история не растёт;
- APK: 0 разрешений, 0 сервисов, 0 провайдеров, 0 ресиверов, один dex,
  нативного кода нет, следов Google нет, подпись v1+v2+v3;
- в собранной странице нет стрелок и `for..of`, весь русский текст на месте.

## Ориентация

Весь сборник в альбомной ориентации: четыре игры из пяти сделаны на
альбомную, арена COURIER сверху просто становится шире, и это ей не
мешает.

## Чего нет

Ни одного внешнего изображения: иконки в меню нарисованы геометрией в
SVG, вся графика игр — кодом на Canvas 2D. Интернет не нужен, сети
приложение не запрашивает.
