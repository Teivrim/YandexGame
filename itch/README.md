# Листинги itch.io

Тексты, теги и параметры встраивания для всех пяти игр, плюс заметки о
том, как itch себя ведёт. Файл `listing-copy.js` — источник правды:
описания на сайте не выгружаются, а изменения в редакторе не
версионируются, поэтому тексты хранятся здесь.

## Что выяснено пробами

Не догадками, а проверками — каждое утверждение ниже стоило неудачной
попытки, поэтому записано, чтобы не повторять.

### Короткое описание мерится в байтах, а не в символах

Ошибка прилетает такая: `Short Description — expected text between 1 and
120 characters, or empty`. Русский текст в 69 символов — это 125 байт
в UTF-8, и его отклоняют. Проверено: 52 символа (84 байта) проходят,
69 символов (125 байт) нет. Отсюда правило: **короткие описания держатся
в пределах ~50 знаков**. В `listing-copy.js` все пять укладываются в
77–94 байта.

### `game[description]` и `game[tags]` — скрытые поля

У обоих `offsetParent === null`: за ними стоит JS-модель (Redactor для
описания, виджет тегов для тегов). Отсюда два следствия.

1. Установка `value` через native setter **не работает**: страница при
   сохранении берёт значение из модели и затирает наше. Проверено —
   значение в DOM менялось, после перезагрузки было старое.
2. `document.execCommand('insertText')` на скрытом поле **молча не
   срабатывает** и возвращает `false`.

Работает только одно: **временно показать поле, ввести текст настоящими
событиями, снова скрыть**. Проверено на всех пяти листингах.

### Отказ сохранения выглядит как ошибка в другом поле

Когда не проходило короткое описание, itch отклонял **всё** сохранение
целиком, включая теги и описание. То есть одна непрошедшая проверка
блокирует запись всех полей формы. Отсюда правило проверки: не
смотреть на текст баннера ошибки (он залипает и показывает ошибку от
предыдущей попытки), а **перезагружать страницу и читать, что реально
сохранилось**.

### У каждого размера на CDN свой хеш

`https://img.itch.zone/<base64>/<W>x<H>/<hash>.png` — подставить тот же
хеш в другой сегмент размера даёт 404. Перебором полноразмерный URL не
находится. Он лежит в HTML публичной страницы: там перечислены все
размеры каждой картинки (`250x600`, `original`, `347x500`, `794x1000`).
Отсюда и решение брать `794x1000` для шапки описания: 255–285 КБ вместо
840 КБ у оригинала.

### Прочее

- Описание принимает **HTML, но не markdown**: Redactor экранирует `**`
  и `###`. Проверка на мусор — `/\*\*|\n#{1,3} /` по сохранённому
  значению поля.
- Снимки в галерее грузятся **лениво**: пока не прокрутишь блок, в DOM
  не будет ни одного `img`. Проверять галерею на свежей странице
  бесполезно — картинок ноль.
- У карточки снимка есть скрытое поле `screenshot[<id>][position]`,
  по нему снимок опознаётся надёжнее, чем по картинке. Кнопки:
  `move_screen_up_btn`, `move_screen_down_btn`, `delete_screen_btn`.
- В форме проекта **две** кнопки `Save`, обе видимые. Брать последнюю.
- Кнопка запуска на странице игры читается **«Run game»**, не «Play».
- Страницы тяжёлые: `document.body` бывает `null`, а `readyState`
  застревает на `"loading"`. Надёжный признак готовности — наличие
  кнопки `Save`.
- Загрузка файла: `Upload files` → `DOM.querySelector` ищет
  `input[type=file]` → `DOM.setFileInputFiles` → ждём исчезновения
  `uploading` → `Save`.
- Галерея снимков на странице правки и список загрузок — разные
  блоки. Список загрузок читается текстом: у работающей записи есть
  строка `This file will be played in the browser` и время загрузки.

## Что было исправлено при полировке

- **BASTION встраивался 640×360** вместо 1280×720 — остался размер по
  умолчанию.
- **VECTOR был без короткого описания и без тегов** — оба поля пустые.
- **Жанр не задан** был у четырёх игр из пяти.
- **Ни в одном описании не было картинки.**
- **В `neon-bastion/game.js` был двойным образом перекодирован весь
  русский текст** — игра показывала «Р°РјРїСѓР»СЃ» вместо «Импульс».
  Подробно в `../neon-bastion/README.md`, коммит `93c9b02`. Нашёл
  баг кадр для баннера, на котором подписи кнопок оказались нечитаемыми.
